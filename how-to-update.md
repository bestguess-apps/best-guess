# How to update Best Guess

This repo (bestguess-apps/best-guess) is the source, and it's what the website publishes. `index.html` is the whole app in one file.

## Release steps
1. Get the current files from this repo.
2. Edit `index.html`. Keep the app in one file.
3. Run `python3 rebuild.py <new version>` in the repo folder. It refreshes the privacy lock, rebuilds `selftest.html` from the app, and sets the version in `index.html`, `sw.js` and the self-test. After any script edit without a version change, run `python3 rebuild.py` on its own. `python3 rebuild.py --check` changes nothing and says whether the lock, the self-test and the versions are right (Publish runs it and stops if not).
4. Run the self-test in headless Chrome: the toolkit's `release-check.sh` does it at 3 sizes. Before a release, also run it in a few time zones with daylight saving (it tries the forecast date around each clock change in the browser's own zone). Test everything the verify routine asks for. For the engine and the Track record step: `node --test test_engine.mjs test_add_record.mjs`. For the fetcher: `python3 test_fetch_prices.py`. Publish runs them all and stops if any fails. For screens, put a made-up `prices.json` (with a `record` from `node add_record.mjs prices.json`) next to index.html while testing, and remove it after: it's never committed.
5. Save the changed files to this repo, plus a new CHANGELOG.md entry and an update to PROGRESS.md.
6. GitHub does the rest: the "Publish" workflow fetches prices, adds the Track record and publishes the site, and "Tag new versions" adds the `vX.Y.Z` tag. Check that both runs passed.
7. Open the live site on a real iPhone: check About → Data check, then About → Run self-test, and record the result in CHANGELOG.md and PROGRESS.md.

Screens and sheets for the accessibility check (toolkit `a11y-check.mjs`, or `release-check.sh` with one `--click` each): the main screen, `--click '#tab-look'` (Worth a look), `--click '#tab-look' --click '#lookBody .coin'` (a forecast opened from it, with the Add button when that coin isn't on the list), `--click '#tab-record'`, `--click '#tab-record' --click '#recordBody summary'` (a coin opened), `--click '#todayBody .coin'` (a forecast), `--click '#todayBody .coin' --click '#decideSum'` (a forecast with Before you decide open), a forecast with the big swing note (made-up prices with one coin swinging much more than usual: `--click '#todayBody [data-coin="<that id>"]'`), `--click '#editBtn'`, `--click '#aboutBtn'`. Pass `selftest.html` as an extra page (its intro). The self-test's report, after its reloads: `node a11y-check.mjs --click '#st-go' --click 'main' --click 'main' --click 'main' --click 'main' --click '#st-copy' <url>/selftest.html` (the `main` taps only wait; wrap it in `timeout 150`, since a tap can land mid-reload and hang it, then run it again). Check the Track record both with a record in prices.json and without one. Check Worth a look both on a day with picks and on a "Nothing stands out today" day. Check the main screen, Worth a look and a forecast with saved prices 3 days old (the warning) and 8 days old (paused) too: change `fetched` in the made-up prices.json.

## Things that must not break
- **The privacy lock.** `index.html` carries a Content-Security-Policy that only lets scripts run whose exact sha256 fingerprint is listed, and only lets the page talk to this site and `https://api.coingecko.com`. Any script edit changes the fingerprint, so run `rebuild.py`. The Publish workflow refuses to publish a stale lock.
- **The web address and storage key never change.** The site is `bestguess-apps.github.io/best-guess/` and the storage key is `best-guess-v1`. The offline cache name must start with `best-guess-`, and sw.js only clears caches with that prefix.
- **prices.json is untrusted.** The app and the fetcher both check every field and build fresh objects from known fields only. Coin names go on screen as text only (the `el()` helper), never as HTML.
- **Be kind to CoinGecko's free limit** (about 5 requests a minute per internet address). The fetcher waits 13 seconds between requests, reuses fresh files and history it already has, and backs off when CoinGecko says it's busy. The app does at most one live check a minute.
- **If anything fails, keep the last good prices.** The fetcher never publishes an empty file over a good one.
- **APP_VERSION** in the app and the version in sw.js must match. `rebuild.py` sets both. "Tag new versions" reads APP_VERSION from `index.html`, so keep it written as `const APP_VERSION = "X.Y.Z";`.
- **The engine stays plain functions** in its own `<script>` block (`const BestGuessEngine`), with no screen, storage or network, so test_engine.mjs can load it from index.html. Keep the honesty tests passing: if the no-pattern test fails, the engine is claiming more than it knows.
- **Replays never see the future.** Anything that replays the engine goes through `prepare(samples, asOfDay)` and gives it only the prices up to that day. The Track record's replay is `replayCalls()` in the engine; the price 7 days later is used only to score a call. The no-future and planted-bug tests in test_engine.mjs must keep passing.
- **The Track record is worked out at publish time** by `add_record.mjs` and travels inside prices.json as `record` (counts only). The app checks every number and ignores a record that doesn't add up. If the step fails, Publish shows a yellow note and still publishes prices. Show the record as it is, even when it's bad, and keep "too few to tell."
- **Old prices are said, never hidden.** The engine's `priceAge()` decides: saved prices 2 days old get a yellow warning at the top, even when live prices work (forecasts are built on the saved history); at 7 days, forecasts and Worth a look pause until prices update. The Track record still shows. About → Data check says it too.
- **The easy guess is only shown.** `easyGuess()` takes whichever way more of the leans' prices went ("up" on a tie), using `rose` in the record. It never changes verdicts, confidence or picks. `rose` is optional: a prices file from before 1.1.0 doesn't have it, and the app then just doesn't show the line. When it's there it must be a whole number no bigger than the leans, or that score isn't used.
- **Worth a look stays strict.** The engine's `standouts()` decides the picks, never the screen: medium or high confidence after the cap, past leans right at least 55% of the time (`PICK_RIGHT`), 3 at most, and none at all without a track record to test against. The honesty test in test_engine.mjs must keep passing: with no real pattern, most days say "Nothing stands out today." It looks at all 25 coins using saved prices; the live check still asks only about the watchlist.
- **The record can only lower confidence** (`capConfidence()`), never raise it or change a lean.
- **The forecast's plain words come from the engine (1.2.0).** `inShort()` picks the "In short" sentence from the lean, the confidence after the cap and the record (the coin's own leans, else all coins). It must keep saying plainly when past leans did no better than a coin flip or the easy guess, and keep its honesty test passing. `lastCall()` makes last week's call through the same `callAt()` as the Track record's replay (no peeking) and scores it with `scoreCalls()`. `bigSwing()` and `pastYear()` are plain functions with tests. The screen only shows what they return. Nothing in them says what to do with a coin: no buy or sell wording, alerts or price targets.
- **"Not financial advice" stays on every forecast,** now one short line with two facts from that coin's own daily prices (`pastYear()`), and a plain fallback when it has none.
- **No coin logos.** They'd load from CoinGecko's image servers and share people's internet address with them. The app shows a symbol badge instead.
- **Actions pinned to full commit SHAs** with a version comment, least permissions per job. Look up the real SHA when updating.
- **The keepalive job keeps prices coming.** GitHub pauses scheduled runs in public repos after 60 days without changes. Publish's `keepalive` job turns the workflow on again once a day (on the 00:17 UTC run, and on Run workflow), which starts that count over. It's the only job with `actions: write`, it runs none of this repo's code, and it uses only the `gh` tool on GitHub's runners. GitHub doesn't document that turning a workflow on restarts the count (other keep-alive tools rely on it), so the app's old-prices warning is the backup. Keep the 00:17 cron line exactly as the job's `if:` names it.

- **The self-test.** `selftest.html` is built by `rebuild.py`: the app on its own storage key (`best-guess-selftest-v1`), plus two scripts kept in `selftest.html` itself: the made-up network (first script) and the runner (last script). Edit only those two there; everything else comes from `index.html`. It keeps the standard hooks (`#st-go`, and `#st-sum` whose first line says PASSED or FAILED), a Copy report button, and no feedback email. It reloads the page 3 times (sessionStorage `best-guess-selftest-v1-run`) to check what comes back on reopening, and wipes only its own keys at the end. Its only real requests are this site's `prices.json` and one CoinGecko price, and its intro says so. Publish copies it to the site; sw.js doesn't save it, so the offline copy stays the app.

## Phone steps
- **Run the publish now:** repo → **Actions** → **Publish** → **Run workflow** → **Run workflow**.
- **Check a run:** repo → **Actions** → tap the run. Yellow notes mean the fetcher fell back to older prices for something, or the track record couldn't be worked out.
- **If the app says saved prices are old, or the schedule stops:** repo → **Actions** → **Publish**. If it says the workflow is disabled, tap **Enable workflow**. Then **Run workflow** → **Run workflow**, and check the run passed.
